# Phase G — Orbs Vertical (Plan)

Status: **✅ SUPERSEDED BY PHASE I (shipped) — reconciled 2026-06-27.** Forged orb classes shipped end-to-end via
Phase I (engine + generator): a class can declare an `orb_pool` and channel/evoke/scale orbs, generated by the LLM.
This plan's goal is fully realized — see `PHASE_I_FORGED_ORBS_PLAN.md`. Original status preserved below. — Supersedes
the Phase G sketch in `VOCAB_EXPANSION_PLAN.md`. Builds on
the **orb-HUD spike (SUCCESS, 2026-06-16)** and Phase B (forged classes). Goal: a forged class can *be* a
Defect-style **orb class** — start with orb slots, and channel / evoke / scale orbs from its cards — generated
end-to-end by the LLM/website.

## What the spike already proved (so we don't re-litigate)
- Orb **HUD renders** for a non-Defect modded character; a channeled Lightning orb sits in a slot and **fires its
  passive at end of turn** (showed 3 = canonical value; `ToMutable(0)` did NOT zero it). Log clean.
- A **card** can `OrbCmd.AddSlots` + `OrbCmd.Channel` with no character-level orb infra. The execution-path ops
  `gain_orb_slot` + `channel_orb` (Lightning hardcoded) already live in EffectRunner/DataCard/ForgedCards, **kept
  out of the LLM contract**. Phase G generalizes them and opens them to the generator.

## Confirmed API (reflection, `_modref/reflect/dump.txt`)
- `OrbCmd.AddSlots(Player, int)` (per-combat slots), `Channel(ctx, OrbModel, Player)`,
  `EvokeNext(ctx, Player, bool dequeue)`, `Evoke(ctx, Player, OrbModel, bool dequeue)`,
  `IncreaseBaseOrbCount(Player, int)`, `Replace(old, new, Player)`.
- Orbs: `Lightning/Frost/Dark/Plasma/GlassOrb` in `MegaCrit.Sts2.Core.Models.Orbs`; fetch a canonical via
  `(OrbModel)ModelDb.Get(typeof(LightningOrb))`, instance via `.ToMutable(int initialAmount)`.
- `FocusPower : PowerModel` (`ModifyOrbValue`) → fits the **existing `apply_status` path** as a self-buff.
- **STARTING SLOTS (the ex-long-pole, now resolved):** `CharacterModel.BaseOrbSlotCount` is a virtual property
  (`Defect` overrides it). A forged orb class just overrides it → starts with N slots. `Player.BaseOrbSlotCount`
  is the runtime mirror (get/set). **No combat-start hook needed.**

## G1 — Generalize the orb card ops (vocab)   (effort: LOW–MEDIUM)
The standard 7-touchpoint pattern (EffectRunner / DataCard / ForgedCards{SupportedOps+Describe+VocabVersion} /
cardgen.py / VOCABULARY.md / card.schema.json), now extended to the contract (G3) since orbs are proven.

- **`EffectSpec` += `string? Orb`** (the orb type for `channel_orb`). `ForgedCards.ParseEffects` reads `"orb"`.
- **`channel_orb`** — params `orb` (lightning/frost/dark/plasma/glass) + optional `amount` (count, default 1).
  EffectRunner: `var t = OrbTypeFor(e.Orb); for n in amount: OrbCmd.Channel(ctx, ((OrbModel)ModelDb.Get(t)).ToMutable(0), card.Owner)`.
  `OrbTypeFor` = a string→Type map. (Generalizes the spike's hardcoded Lightning.)
- **`evoke`** — `amount` (count, default 1): `for n: OrbCmd.EvokeNext(ctx, card.Owner, dequeue:true)`.
- **`gain_orb_slot`** — `amount`: `OrbCmd.AddSlots(card.Owner, amt)` (already spiked; promote to real + contract).
- **`focus` status** — add to the existing status machinery: `WithPower<FocusPower>` in DataCard, `FocusPower`
  in the EffectRunner status switch, add `"focus"` to `SupportedStatuses` **and `EffectRunner.SelfBuffStatuses`**
  (self-buff), name "Focus" in both `Describe`s. No new op — reuses `apply_status`.
- **Validation:** `channel_orb` requires a valid `orb`; `orb` only allowed on `channel_orb`; `evoke`/`gain_orb_slot`
  amount ≥1. Bump `ForgedCards.VocabVersion` → 6.
- **Display:** counts rendered as literals in `Describe` (e.g. "Channel 2 Lightning orbs.", "Evoke.",
  "Gain {n} orb slot(s).") — counts don't upgrade for MVP (note as a limitation; promote to vars later if needed).

## G2 — Orb classes (character integration)   (effort: LOW, thanks to BaseOrbSlotCount)
- **`CharacterSpec` += `int OrbSlots = 0`.** `Engine/ForgedCharacters.cs` reads `"orb_slots"` from
  `user://forged/characters/KK.json`.
- **`slotgen.py`:** each `ForgedCharacterSlotKK : PlaceholderCharacterModel` adds
  `public override int BaseOrbSlotCount => ForgedCharacters.SpecForClass(K).OrbSlots;` (one line). A class with
  `orb_slots: 3` starts every combat with 3 slots → channel from turn 1; HUD shows because slots exist.
- Empty/non-orb classes keep `orb_slots: 0` (no orb HUD — unchanged behavior). Verify `BaseOrbSlotCount` is
  `virtual`/overridable on the BaseLib `PlaceholderCharacterModel` chain (it's virtual on `CharacterModel`;
  confirm BaseLib doesn't seal it — quick check during build).

## G3 — Open it to the LLM (contract + website)   (effort: LOW–MEDIUM)
- **`VOCABULARY.md` + `card.schema.json`:** add `channel_orb` (+ `orb` enum), `evoke`, `gain_orb_slot`, and the
  `focus` status. Guidance: orbs are a **class identity** — only generate orb cards for an orb class; pair
  channel with evoke/Focus payoffs; keep slot counts small (3–4).
- **Character contract:** add `orb_slots` to the class/character schema + `class_forge.py` blueprint so the
  generator can design a coherent **orb archetype** (channel-engine + evoke-burst + Focus-scaling), gated to
  "this is an orb class."
- **`bts1.py VOCAB_VERSION`** sync to the C# `VocabVersion` (currently lagging at 2; bump to 6) so shared import
  codes carry the orb vocab. (Website/import-code path only.)

## G4 — Test & verify   (effort: LOW)
- **Per-op forged cards** (data path): channel each of the 5 orb types, `evoke`, `gain_orb_slot`, a `focus` card.
- **A test orb CLASS** (`characters/KK.json` with `orb_slots: 3`) whose starting deck channels/evokes →
  verify: HUD present from turn 1, channeling fills slots, full-slot channel evokes the oldest, evoke card works,
  Focus scales orb output, end-of-turn passives fire. Watch `godot.log`.

## MVP cut lines
- **MVP:** Lightning + Frost + Dark, ops `channel_orb`/`evoke`/`gain_orb_slot` + `focus`, ONE forged orb class with
  starting slots, in the contract. Plasma/Glass and orb-specific synergy cards (e.g. "evoke without removing")
  follow once the core reads well.
- Keep one orb class for the first cut (capacity is 4 classes from Phase B; an orb class is just one of them).

## Risks / things to verify in-game (not blockers — the API is all present)
- **Dark orb** accumulates from a base; `ToMutable(0)` may start it at 0. If a channeled Dark shows 0/doesn't
  grow right, pass the canonical's base as `initialAmount` (per-orb-type initial value in `OrbTypeFor`).
- **Evoke order:** `EvokeNext` (oldest) vs `EvokeLast` — confirm which reads as "evoke" for our cards.
- **Glass/Plasma** semantics (STS2 may differ from STS1) — verify behavior before contract guidance.
- **`FocusPower`** `AllowNegative` / stacking — confirm Focus scales Lightning/Frost/Dark as expected.
- **`BaseOrbSlotCount` not sealed** in the BaseLib character chain (compile check).

## Sequencing
G1 (ops, data-path only) → G4a (test ops via forged cards) → G2 (class starting slots) → G4b (test an orb class)
→ G3 (contract + website + a real forged orb class). Land G1+G2 and verify in-game **before** opening the contract
(G3), so the generator only ever sees orb vocab that's proven to play.
